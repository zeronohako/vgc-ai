# vgc-ai

## Goal
A dashboard that analyzes a Pokémon VGC position (4 active Pokémon) and shows the best moves, plus which 4 to bring and 2 to lead. **Not** a ladder bot. Background research: `vgc-bot-research-summary.md`.

**Direction (2026-11-05): Reg M-C, mikumiku37's design.** A policy/value network trained by PPO self-play in Ninjask (no human games, only a team pool), with the one-turn matrix search + regret matching we already have at play time; the network's value replaces the hand-written score at the leaves. Build order: M-C team pool → Rust extension (batched stepping, encoder, action masks) → network + PPO → network in the search → bring/lead → UI. The heuristic stays as the baseline the network must beat; progress is measured **bot vs bot**, agreement with human replays is only a weak signal.

## Status (2026-11-05)
```
.venv/bin/python analyze.py <replay_id> <turn> [--side p1|p2] [--seeds 16] [--top 5] [--depth 2 --k 8 --seeds2 4]
.venv/bin/python test_analyze.py                  # loader/feature checks vs the engine, ~3 s
.venv/bin/python check_positions.py [--grid] [--cache FILE.pkl] [--depth 2 ...]   # agreement with humans, ~76 s on 12 workers (depth 2: ~13 min)
```
Pipeline: replay log → position at start of `<turn>` in Ninjask → every joint action for both sides → each pair played with N seeds → feature vector per cell → score = `F @ WEIGHTS` → regret matching → ranked moves + opponent's likely plays. `--depth 2` re-values a top-k cut by the one-turn game of each resulting position (below).

**Evaluator** (`FEATURES`/`WEIGHTS` in `analyze.py`, my side minus foe): hp (per mon 0.5 alive + 0.5·HP fraction; ±10 for a win) 1.0, Tailwind turns left 0.15, boost stages 0.08 (all stats equal), screens (Reflect + Light Screen turns, Veil = both) 0, protect (Protect-type moves chosen this turn) 0, status per mon slp/frz −0.3, par/brn/tox −0.15, psn −0.1. Ignores Trick Room (in 78/324 M-B games), Encore/Perish/redirection value. Weight tuning is done (coordinate search kept these weights; a flat Protect penalty only hurts). Not worth more hand-tuning now: the network replaces it.

**Agreement with humans** (`check_positions.py`: 40 random positions, seed 0, plus 3 dev; "worse" = share of our options ranked strictly above the human's, 0 = our top pick, 0.5 = random; players are mostly unrated Bo3 ladder players). 1-ply on the 43 positions (86 decisions): fresh 0.247 (human = our top pick 10/80, top 10% 31/80), dev 0.130 (1/6, 4/6). The earlier 0.245/78 lacked two positions the old switch match skipped.

**2-ply search** (`search2`, `--depth 2`; built and verified, not tuned, parked by the direction change). The full one-turn matrix picks the top-k actions per side (EV vs the opponent's mix, plus anything its equilibrium plays ≥1%); each cut cell is played with `--seeds2` seeds and each resulting position is valued by its own full one-turn matrix (1 seed per cell, seeds offset from the root's) solved by LP; fainted mons are replaced first as a small simultaneous game; a win is ±10. `deepen` spreads children over processes. Dev position, k 8 × 8 × 4 seeds = 256 children: 11 s on 12 workers; all 43 positions: 12.6 min. **No gain in agreement:** fresh 0.251 vs 0.247 for 1-ply (top pick 4/80 vs 10/80, top 10% 29/80 vs 31/80), dev 0.147 vs 0.130. Inside the cut (41/86 decisions with the human's action in it) the human's mean rank is 2.91 vs 2.56 for 1-ply (2-ply better 16, worse 22) and its equilibrium probability 0.165 vs 0.238 (uniform 0.122). Untested: whether it plays *stronger* (a bot-vs-bot question). Weak spots: 1 seed per child cell makes child values noisy and biased, leaves are still the one-turn heuristic, pivot switch-ins take the first legal option.

### What we learned
- **Position loading:** `Tracker.world()` works on spectator logs, but the tracker's *own* side is garbage without requests (HP as %, wrong stats). Workaround in `load_position`: build each side from the *other* player's view (where it's the foe), merge the two projections, `Battle.from_projection`. The 4 brought Pokémon come from the whole log via the `{"brought": [idx]}` assumption. Spreads are hidden in OTS; Ninjask's default guess is used. `Battle.from_projection(dx, b.projection(), 0)` reproduces `b` exactly (0/3931 cells differ), which is how search workers get the position.
- **Lost state on load:** the projection drops the `stall` volatile, so `stall_streaks` rebuilds it from the log (`{"counter": 3**n, "duration": 1}`); without it a repeat Protect always works.
- **Speed (~60 µs per simulated cell):** `copy + reseed + choose×2` with logging ≈ 25 µs; `request` + `json.loads` ≈ 70 µs per side and `projection()` + `json.loads` ≈ 400 µs, so neither is called per cell. Everything scored is rebuilt from the turn's omniscient log, which has exact HP: HP/status (`apply_hp_log`; even Regenerator's heal is logged, as `-heal ... [silent]`), boosts (`apply_boost_log`), side conditions (`turn_conds`: root counted down, `-sidestart` sets Tailwind 3 / screens 4 turns left, `-sideend` sets 0, so natural expiry is free; only Light Clay screens and Court Change read the projection). All three checked against the engine in `test_analyze.py`. A C-level `startswith` prefix filter before splitting lines halves the parsing cost. Dev position 61×55×16 seeds: 16.1 s → 3.2 s. Game values by LP (`game_value`, scipy HiGHS: ~5 ms for 60×55, vs ~140 ms for 5000 regret-matching iterations).
- **Pivot moves:** U-turn/Volt Switch/Parting Shot pause the turn for a switch-in; `finish_turn` answers with the first legal switch-in so cells are scored after upkeep.
- **Illegal actions:** `joint_choices` lists switches even when trapped (Shadow Tag etc.). `payoff_matrix` drops rows/columns rejected everywhere before mixed cells.
- **Human switches** match by name *or* species (`check_positions.matches`): the log's nickname can be unknown to the rebuilt battle (EARFQUAKE = Garchomp before it's revealed), and a name can differ from its forme (Sinistcha = Sinistcha-Masterpiece).

## Next steps
1. **Reg M-C team pool** (~1,000 teams; mikumiku37 used ~1,260): scrape Showdown M-C Bo3 replays (polite rate, generic user agent), take both `|showteam|` teams, dedupe (a Bo3 repeats teams; dedupe on the sets ignoring order), keep `team_problems == []`, prefer higher ratings; save one packed team per line (`data/teams_regmc.txt`) plus provenance (replay id, rating, date). Spreads: Ninjask's default guess first; later the most common spread per species from usage stats or tournament pokepastes. The same logs give M-C human positions, replacing the M-B replays in `check_positions`. Then switch `FORMAT`.
2. **Rust extension** (install rustup, `pip install maturin`): one crate in this repo depending on `ninjask` (feature `python`, same pyo3 0.30), registering Ninjask's classes via `ninjask::python::register(m)?` and declared under the `ninjask.extension` entry point, so `import ninjask` and our functions share one `Battle` class (README "Embedding in another extension"). First functions, each with a parity test against the Python version: legal joint actions + masks; batched self-play stepping (N battles, GIL released, rayon over cores); observation encoder; optionally the `payoff_matrix` cell loop (speeds up the heuristic baseline too).
3. **Encoder + action space** (spec in Python first, then Rust): own side + foe as seen + static dex data; per-slot action = move × target × mega, switch, pass; slot 2 conditioned on slot 1, legality mask on the pair.
4. **Policy/value network + PPO self-play** (PyTorch; small transformer; terminal reward; later ~50% past snapshots, PFSP). CPU smoke runs here, real runs on a rented GPU.
5. **Bot-vs-bot arena:** network (± search) vs the heuristic 1-ply baseline, both sides of each pairing, from M-C team-pool matchups. The main metric from here on.
6. Network value at the leaves of the one-turn search; then **bring/lead** (15 bring sets × 6 leads = 90 options per side) and the **dashboard UI**.
